# I18n (国際化) ガイドライン

Rails の I18n 管理に関するルールとパターン。

---

## 基本方針

- デフォルト言語: 日本語 (ja)
- 翻訳の置き場所は **2 系統ある**。混ぜると二重定義になるので、下表で必ず振り分ける

### 翻訳の置き場所

| 種別 | 置き場所 |
|------|---------|
| ViewComponent 内の表示文言 | sidecar `app/views/components/**/component.yml` |
| activerecord / activemodel の属性名・モデル名 | `config/locales/ja.yml` |
| enum ラベル (`ja.enums.*`) | `config/locales/ja.yml` |
| controller の flash メッセージ | `config/locales/ja.yml` |
| ページタイトル (`content_for(:title) { t(".title") }` の lazy lookup) | `config/locales/ja.yml` |

**ビュー/コンポーネントの表示文言は sidecar に置く。** `ja.yml` の役割は上表の 4 つに限る。

---

## ViewComponent の sidecar 翻訳

`app/views/components/foo/bar/component.rb` の翻訳は、同じディレクトリの
`component.yml` に置く。ViewComponent がコンポーネント自身の名前空間として読み込む。

```yaml
# app/views/components/catalogs/list/component.yml
---
ja:
  empty_message: 商品カタログがまだ登録されていません
  empty_hint: 新しい商品カタログを登録してください
```

```erb
<%# app/views/components/catalogs/list/component.html.erb %>
<%= t(".empty_message") %>
```

sidecar のキーはコンポーネントのルート直下にフラットに並べる。`ja.catalogs.list.empty_message`
のようにパスを再現してはいけない。実例は
`app/views/components/pos/sales_history/daily_summary/component.yml` と
`app/views/components/catalogs/list/component.yml` を参照。

### ja.yml に書いても届かない

**ViewComponent 内の `t(".key")` はコンポーネント自身の名前空間に解決される。**
`config/locales/ja.yml` は参照されないため、同名キーを ja.yml に置いても表示には反映されず、
誰も引かない孤立キーとして残るだけになる。

過去にこの取り違えでビュー文言を ja.yml と sidecar の両方に書いた二重定義が発生し、
issue #292 で ja.yml 側の孤立キーを大量に削除する後始末が必要になった（コミット 9163cd4）。

- コンポーネントに文言を足すとき、ja.yml は触らない
- 文言が出ないときに ja.yml へキーを足して解決しようとしない。sidecar のキー名を疑う

### テストでの検出範囲

`config/environments/test.rb` で `config.i18n.raise_on_missing_translations = true` を
有効にしてある。sidecar への書き忘れ（ja.yml にだけ書いた場合）は、そのコンポーネントを
描画するテストが `I18n::MissingTranslationData` で落ちるため検出できる。

ただし**逆方向は検出できない**。sidecar と ja.yml の両方に書いた二重定義は、sidecar 側が
引かれて描画が成功するため、ja.yml 側の孤立キーはテストを通過して残り続ける。
置き場所が一方だけになっているかは、書く時点で自分で確認する。

なお `development.rb` 側はコメントアウトしたままにしてある。開発中に文言未定義で
画面全体が落ちると手戻りが大きいため。

## モデル・カラム追加時のチェックリスト

新しいモデルやカラムを追加した際は、**必ず** `config/locales/ja.yml` を更新する。
（属性名・モデル名は sidecar ではなく ja.yml が置き場所）

### 新規モデル追加時

```yaml
ja:
  activerecord:
    attributes:
      model_name:        # スネークケースで追加
        attribute1: "属性1の日本語名"
        attribute2: "属性2の日本語名"
```

### 既存モデルにカラム追加時

該当モデルのセクションに属性を追記する。

---

## 命名パターン

| 属性タイプ | 日本語表記例 |
|-----------|-------------|
| email | メールアドレス |
| name | 名前 |
| password | パスワード |
| created_at | 作成日時 |
| updated_at | 更新日時 |

---

## 現在の構造例

```yaml
ja:
  activerecord:
    attributes:
      employee:
        email: "メールアドレス"
        name: "名前"

  custom_errors:
    controllers:
      # エラーメッセージ定義
```

---

## 注意事項

- マイグレーション作成後、ja.yml の更新を忘れない
- バリデーションエラーメッセージが正しく日本語表示されるか確認する
- `rails console` で `ModelName.human_attribute_name(:attribute)` を使って確認可能
- ビュー文言を追加したら、置き場所が sidecar と ja.yml のどちらか一方だけになっているか確認する
