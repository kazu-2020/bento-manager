# ADR-0006: 弁当販売履歴は集計を弁当に絞り、取引一覧は全商品を並べる

- **状態**: 承認
- **日付**: 2026-08-22

## 背景

弁当販売分析は `Catalog.bento` で母集合を絞っている。数えるのは弁当だけであり、それは「次にどの弁当を何個積むか」に答えるためである。

一方、販売履歴（カレンダー側）は何も絞っていない。`Sales::HistoryCalendar#daily_totals` は `Sale#total_amount` を合計し、`#daily_breakdown` は `items: :catalog` を join したまま弁当で絞らない。つまりサラダが混ざっている。同じアプリの中で、隣り合う 2 つの分析画面が違うものを数えていた。

この画面を「弁当販売履歴」と改めるにあたり、名前と中身を一致させる必要が出た。

**しかし、素直に全部を弁当へ絞ると帳簿が壊れる。**

取引一覧はその日の販売を 1 件ずつ時刻・商品・個数・金額で並べる。ここから弁当だけを抜くと、弁当 600 円 + サラダ 350 円で 950 円受け取った取引が 600 円と表示される。**画面上の金額と、母が実際に受け取った金額が食い違う。**取引一覧は分析の道具であると同時に、その日いくら受け取ったかを確かめる帳簿でもある。

## 決定

**数えるものは弁当だけ、並べるものは全部とする。**

| | 母集合 |
| --- | --- |
| ヒートマップ（販売個数・消化率） | 弁当のみ |
| 月次サマリ（月合計・1 日平均・最高日） | 弁当のみ |
| 日別内訳（顧客タイプ別の商品別個数） | 弁当のみ |
| 日次サマリの取引件数 | 全商品（取引の件数であって商品の数ではない） |
| 日別詳細パネルの取引件数 | 全商品（同上） |
| 取引一覧（時刻・商品・個数・金額） | 全商品。金額もそのまま |

**弁当が 0 個の日をどう数えるかは、母集合とは別の軸で決まる。**集計を弁当に絞ると、サラダしか売れなかった日が「販売はあったが弁当は 0 個」という新しい状態として現れるため。

| | 弁当 0 個の日 |
| --- | --- |
| 月次サマリの 1 日平均の分母 | 数える |
| 月次サマリの最高日 | 外す |
| ヒートマップの濃淡の閾値 | 外す |
| ヒートマップのセル | 出す（休みとは区別する）。ただし色はつけない |

1 日平均は積込数を決めるために最初に見る数字なので、店を開けたのに売れなかった日を分母から落とすと平均が上振れし、積みすぎる方向に読ませる。一方で最高日と濃淡は「どの日がよく売れたか」を示すためにあり、0 個の日はそもそも比べる対象ではない。**数える目的が違うので、同じ 0 個の日の扱いが分かれてよい。**

境界は「集計か、一覧か」に引く。**集計は弁当の売れ方を見るためにあり、一覧はその日の取引そのものを見るためにある。**目的が違うので母集合が違ってよい。同じ画面の中で母集合が 2 つ存在することを、欠陥ではなく仕様として引き受ける。

## 検討して採らなかった案

- **取引一覧も弁当だけに絞る** — 名前と中身は完全に一致するが、上記の通り表示金額が受取額と食い違う。帳簿としての用途を捨てることになり、これは金額を集計値から全廃した際に「取引 1 件ごとの金額は残す」と決めた判断と正面から衝突する。
- **絞らず、名前だけ「弁当販売履歴」にする** — 名前が嘘になる。サラダを数えているのに弁当と名乗る状態は、弁当販売分析と数字を突き合わせた人を確実に混乱させる。
- **名前を「販売履歴」のまま据え置く** — 弁当販売分析と並んだとき、同じ「販売」という語が 2 つの母集合を指し続ける。加えて POS 側の販売履歴とも語がぶつかったままになる。

## 結果

- **日別内訳の合計個数と、取引一覧に並ぶ商品の個数は一致しない。**サラダの分だけ後者が多い。バグではない。
- **サラダしか売れなかった日は、ヒートマップ上は販売 0 個**になるが、取引一覧を開けば行が並ぶ。
- **日別詳細パネルの 2 枠は「弁当の販売数」と「取引件数」になる。**当初は金額の枠を個数に置き換える想定だったが、内訳を弁当に絞った時点で隣の「販売数」と同じ数になるため、日次サマリと同じ 2 枠構成に揃えた。母集合が 2 つ並ぶことが画面上で読み取れる。
- **色のついたセルが全部「1 日平均」より大きい月がありうる。**弁当が売れた日が 3 日（30 / 25 / 20 個）でサラダのみの日が 1 日なら、月合計 75 個・1 日平均 18.8 個・最高日 30 個となり、色のついた 3 セルはいずれも平均を上回る。分母だけが 0 個の日を数えるためであり、バグではない。
- **消化率の分母も弁当だけ**である。当日在庫のうちサイドメニューの行は分母に入れない。
- サイドメニューに 3 つ目の商品が増えても、この境界は「弁当かどうか」のまま動かない。ADR-0005 が示した通り、業務規則が問うのは常に弁当かどうかだけである。
- POS 側の販売履歴（当日の販売一覧・差額精算の入口）はこの決定の対象外であり、弁当もサラダも区別せず並べる。`CONTEXT.md` では「販売履歴」と「弁当販売履歴」を別語として定義した。
